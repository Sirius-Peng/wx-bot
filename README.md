# 微信 AI 助手

接入大模型的微信对话机器人，支持**一对一私聊**与**群聊 @ 回复**。
自带 Web 管理界面与 Electron 桌面版，**双击即可运行**。

---

## 核心结论（先说重点）

1. **个人微信私聊已有官方 API** —— 腾讯 2026-03 通过 OpenClaw 开放了 **iLink Bot API**（微信 ClawBot），合规、零封号、官方维护。
2. **但官方 API 不支持群聊** —— 源码能力声明为 `chatTypes: ["direct"]`，已四重交叉验证（官方包、社区 fork、第三方 SDK、官方仓库 feature request 全部指向同一结论）。
3. **推荐混合架构**：私聊走官方 iLink（合规），群聊走 iPad 协议（承担风险）。把合规风险压缩到只存在于群聊场景。
4. 若业务可收敛到企业内部，改用**企业微信官方智能机器人**（官方支持群聊，零封号）。

原生窗口 + 系统托盘，**关掉窗口后机器人在后台继续静默运行**，可打包成单一安装包。

```bash
cd desktop

npm run pack:mac         # 产出 .dmg
npm run pack:win         # 产出 NSIS 安装包 + 免安装 exe
```

## 快速开始（三步）

### 1️⃣ 启动

| 你的系统 | 操作 |
|---|---|
| **Windows** | 双击 `start-windows.bat` |
| **macOS** | 双击 `start-mac.command` |
| **Linux** | 终端执行 `./start.sh` |

> 首次运行会自动安装依赖（约 1–2 分钟），之后每次启动只需几秒。
> 浏览器会自动打开管理界面 `http://127.0.0.1:8000`。

### 2️⃣ 配置

在「**接入设置**」里勾选要用的通道（微信 / QQ，可同时开），然后各点一次「一键」：

| 通道 | 操作 |
|---|---|
| 微信 | 点「**一键完成配置**」→ 程序装好网关、**并自动取回 Token** → 扫码登录 |
| QQ | 点「**一键部署 QQ 网关**」→ 程序装好 NapCat、写好网络配置 → 页面直接出二维码 |

> Token、网关地址都会自动回填，**不需要你去任何控制台复制**。
> 只有一种情况需要手动填：你用的是别处已经跑着的网关，那就展开「手动指定地址」。

在「**模型与行为**」里：
- 填写大模型 API Key（推荐 DeepSeek）
- 设置机器人的名字和性格

### 3️⃣ 启动

点右上角「**启动机器人**」，完成。

## 没有编程基础？先看这两条

**① 网关会自动帮你装好（微信和 QQ 都是）**

两个通道各自依赖一个本机 Docker 网关，**你不需要自己装 Docker，也不需要敲任何命令**：

| 通道 | 网关 | 一键按钮 |
|---|---|---|
| 微信 | GeWe 协议网关 | 「一键完成配置」 |
| QQ | NapCat（OneBot 11） | 「一键部署 QQ 网关」 |

程序会自动：检测/安装 Docker → 启动服务 → 拉镜像 → 建容器 → 回填地址与 Token → 出登录二维码。

全程只有两处需要你动手（系统限制，无法自动化）：
- 安装 Docker 时**输入开机密码**
- 首次启动 Docker 时**同意许可协议**

界面会明确告诉你当前卡在哪一步、下一步做什么。

> **关于 GeWe Token**：程序会向本地网关调 `tools/getTokenId` 自动换取。
> 上游 `Devo919/Gewechat` 仓库已声明停止提供运行服务与镜像（仅作技术归档），
> 本地旧镜像仍可能可用但**不保证**。取不到时会明确提示，并支持手动粘贴。

**② 需要一个「大模型 API Key」**
到 [DeepSeek 开放平台](https://platform.deepseek.com/) 注册并充值（10 元够用很久），
复制 API Key 填进「模型与行为」页面。

**③ 群聊不会刷屏**
默认策略下，机器人在群里**只有被 @ 时才会回复**。

## 群聊回复策略

默认 **「仅 @ 机器人时回复」**：

```
消息到达
  │
  ├─ 私聊 ─────────────────────────→ 一律回复
  │
  ├─ 群聊，@ 了机器人 ─────────────→ 回复（并 @ 回提问者）
  │
  └─ 群聊，没 @ ───────────────────→ 不回复
```

可在「模型与行为」页切换为 **「智能判断」**，让机器人主动找时机插话：

```
群消息 → ① @机器人 / 唤醒词 ────→ 必回
        ↓ 没命中
        ② 黑名单 / 静默时段 ────→ 必不回
        ↓ 通过
        ③ 启发式打分（阈值 40 分）→ 拦掉约 80%
        ↓ 通过
        ④ 小模型判定该不该插话 ──→ 拦掉约 75%
        ↓ 通过
        ⑤ 冷却 / 配额 / 概率闸门 → 拦掉约 80%
        ↓
        最终约 1~2% 的消息被回复
```

| | 仅 @ 机器人（默认） | 智能判断 |
|---|---|---|
| 私聊 | ✅ 一律回复 | ✅ 一律回复 |
| 群聊 @ 机器人 | ✅ 回复 | ✅ 回复 |
| 群聊未 @ | ❌ 一律不回 | ⚠️ 可能被漏斗捞起来 |
| 唤醒词 / 启发式 / 小模型 | 不启用 | 启用 |
| 默认冷却 | 不限速（@ 了必回） | 60 秒 |

> **为什么默认选「仅 @」**：用户 @ 了机器人却因为概率或冷却没被回复，体验很差，会让人以为机器人坏了。
> 所以这个模式下**不做任何限速与概率控制 —— @ 了必回**。想限速可以在界面上自己设。

**成本控制**：智能模式的判定用免费模型（GLM-4.7-Flash），回答用便宜模型（DeepSeek-V4-Flash）。
日均 2000 条群消息的场景下，判定成本为 **0 元**。

## 两种接入方式的区别

| | GeWe 协议 | 官方 iLink |
|---|---|---|
| 私聊 | ✅ | ✅ |
| **群聊** | ✅ | ❌ **不支持** |
| 合规性 | ⚠️ 逆向协议 | ✅ 腾讯官方 |
| 封号风险 | 中（用专用号可控制） | **无** |
| 部署 | 需自建网关 | 装插件即可 |

> 界面里的「**混合模式**」可以两者兼得：**私聊走官方（合规），群聊走协议（承担风险）**。

## 其他启动方式

### Docker 一键部署

```bash
docker compose up -d
# 打开 http://127.0.0.1:8000
```

会自动启动「协议网关 + 主程序」两个容器。本应用零外部依赖，**不需要数据库**。

### 命令行

```bash
pip install -r requirements.txt
python -m src.server
```

### 环境变量

| 变量 | 默认值 | 说明 |
|---|---|---|
| `WXBOT_PORT` | `8000` | 服务端口（被占用时自动顺延） |
| `WXBOT_HOST` | `127.0.0.1` | 监听地址 |
| `WXBOT_DATA_DIR` | `./data` | 数据目录（配置 + 消息记录） |
| `WXBOT_NO_BROWSER` | — | 设为 `1` 则不自动打开浏览器 |

---

## 数据与隐私

- 所有配置和消息记录都保存在本机 `data/` 目录，**不上传任何服务器**
- 配置文件 `data/config.json` 里含 API Key，权限已收紧为仅本人可读
- 群聊上下文**默认不写入长期记忆**，仅保留 30 分钟会话窗口
- 想备份或迁移，直接拷贝 `data/` 目录即可

## 项目结构

```
src/                        Python 引擎
  server.py                 Web 服务（管理界面 + API + 消息回调）
  runtime.py                机器人运行时（启停 / 状态 / 消息日志 / 扫码登录）
  config_store.py           配置持久化（原子写入 + 密钥掩码）
  orchestrator.py           编排层，串联完整链路
  store_memory.py           会话存储
  web/                      管理界面（零构建步骤：HTML + CSS + 原生 JS）
  core/
    types.py                统一消息结构（换协议不改业务的关键）
    group.py                群聊语义（@检测三格式 / 群昵称 / 发送者解析）
    trigger.py              触发策略（仅 @ / 智能漏斗）
    context.py              上下文装配与压缩
    llm.py                  大模型网关（路由 / 降级 / 成本统计）
    sender.py               拟人化发送（限流 / 延迟 / 分段）
  adapters/
    base.py                 适配器契约 + 能力声明
    gewechat.py             GeWe 协议（私聊 + 群聊）
    ilink.py                官方 iLink Bot API（仅私聊）
    hybrid.py               混合路由（私聊走官方、群聊走协议）

desktop/                    Electron 桌面版
  src/main/                 主进程（窗口 / 托盘 / 后端进程 / IPC / 路径）
  src/preload/              安全桥接
  backend/entry.py          PyInstaller 打包入口
  scripts/                  后端打包 + 图标生成
  electron-builder.yml      打包配置

start-mac.command           一键启动脚本
start-windows.bat
start.sh
docker-compose.yml / Dockerfile
requirements.txt
```

**架构要点**：所有协议适配器都归一化到同一个 `WxMessage` 结构，因此换协议不改业务逻辑；
桌面版把 Python 引擎作为 sidecar 二进制，前端 UI 与浏览器版完全复用。

- 官方 iLink 通道合规、零封号，但腾讯保留随时调整或终止服务的权利，建议保留降级通道。
- 请勿用于营销群发、骚扰等违规用途。
- 请遵守《生成式人工智能服务管理暂行办法》，使用已备案的国内大模型服务。
