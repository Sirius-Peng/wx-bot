# 主动联系：单端可用，双端可共享

状态：v2.1.5 更新，2026-10-15；本次先构建 macOS arm64，Windows 新包待构建机恢复，旧 v2.1.4 安装包不含本功能。

## 开启方法

1. 启动机器人，通过微信或 QQ 私聊一次。在「模型与行为 → 主动联系」刷新联系人。
2. **只使用微信或只使用 QQ：直接选择该端联系人，无需关联身份，也无需开启另一通道。** 若同一个人同时使用两端且希望共享计划，再到「人格知识库 → 微信 ↔ QQ 身份关联」关联（可选），使用消息记录里的**发送者 ID**。不凭昵称猜测是否为同一人。
3. 打开「不定时主动发消息」，保存本卡片，再打开允许联系的联系人开关（联系人即时保存）。默认总开关关闭、联系人未选择；不向群聊主动推送。
4. 默认最近一次收发消息后随机等待 **3～8小时**，每个联系人每天最多 **2条**（已关联的双端合并计算）。默认 **23点至次日8点**免打扰，使用「联网搜索与时间」里的时区。开始、结束时间相同表示关闭夜间免打扰。

间隔可设置0.25～168小时、每日上限1～10条；最长间隔不得小于最短间隔。调度器每15秒检查一次，不是精确闹钟；聊天、静默时段、离线或模型选择跳过时都会延后。重启不集中补发过期计划，未来的计划尽量沿用。

## 共同生活线，而不是两位机器人

- 一个运行时、一个规划器；未关联账号按平台与发送者 ID 独立规划，微信与 QQ 同号也不自动合并。身份关联是可选的同人合并，不是功能准入条件；关联后动态分组。QQ、微信任一端的**入站即刻**更新最近联系时间，不等合并消息处理完；成功回复也刷新共享冷却。
- 每人只有一个随机计划、一个每日额度、一个等待回复状态。只选最近活跃的可用渠道发**一条完整气泡**，不同时向两个账号发相似问候。
- 模型使用当前人格、关系模式、可用长期记忆、当前联系人的近期真实互动和当前时间；已关联双端时才合并两个私聊的记录。主动联系不是虚构的用户提问；没有合适话题时输出 `<SKIP>`，不发送占位消息或故障提示。不会为主动消息额外执行联网查询。
- 主动消息写入所选渠道的助手历史；同人的另一个渠道也能读到近期互动参考。不同用户、未关联账号、群聊上下文不混入。近期参考独立于长期记忆抽取；长期记忆开关仍控制事实召回。
- 任一端出现新输入、用户关闭功能或联系人、关联关系/人格/模型变化时，尚在生成的主动消息作废。发送前还检查双端队列、会话处理锁、当前设置与渠道状态。已经提交到接口的消息不撤回。
- 主动消息发出后，**对方未回复不连续追加**，跨日也不催；解除账号关联不会立即绕过已有等待状态。任一关联账号有新消息后，才重新随机计时。
- 对方单独发“不要主动给我发消息”“别联系我”等直接指令，会暂停当前联系人；已关联时同时暂停两端，日后普通聊天不会自行解除，管理员重新打开联系人开关后恢复。

## 微信与失败处理

微信主动发送需要此前私聊取得的 `context_token`。本功能只使用最近24小时内收到的微信会话凭据（本项目的保守发送策略，并非对平台有效期的保证）；没有可用凭据、通道停止等情况下，在**提交前**才考虑另一个可用渠道。

发送前持久化一次尝试与共享等待状态。接口失败、超时、进程在提交中退出时，QQ可能已经接收，**不自动重试、不切换另一渠道重发**；页面显示结果待确认。微信额外复用主动消息专用草稿ID，和普通回复草稿分开。接口接受只表示提交成功，不表示客户端已读。

计划、账号开关、近期互动与必要微信凭据保存于独立用户数据目录中的 `proactive.json`，文件权限0600；随整套用户目录备份/导入，不写进安装目录。管理API仅返回联系人与计划状态，不返回正文或凭据。记录损坏或落盘失败时暂停主动发送，原文件保留；不影响正常收件/回复，不重新初始化后重复联系。

## 实现与验证

核心：`src/core/proactive.py`；运行时接线：`src/runtime.py`；配置/API/UI分别位于 `src/config_store.py`、`src/server.py`、`src/web/`。

确定性时钟与随机源测试覆盖无需关联的微信单端/QQ单端、未关联联系人隔离、双端共享计划/每日额度、输入抢占、夜间/时区、重启、关联变化、退订、超时不重发、持久发送占位、权限/损坏文件、真实协议入站与出站封装。测试只使用临时目录与模拟接口，不访问真实用户会话或付费模型。
