# 人格优先与渐进记忆

> 本文对应当前v3.0.0源码（开发中，未发布）。记忆文件仍兼容原v3格式；应用版本与记忆格式版本是不同概念。最近已发布v2.1.7仍使用原14/180天阶段策略。新版验收见[v3状态](v3/validation.md)，原数据目录保持不变。

## 人格与了解分开

人格身份、价值观、口吻与关系边界来自人格配置，不从用户记忆自动改写。「人格与记忆」页面管理的是**对用户的了解**，不是角色官设。人格始终保留；摘要和记忆明确标为参考资料，不构成新的系统指令。日常相关召回0—1条；明确追问事实或往事时才最多三条、约400字，不再把所有交流风格无条件插入。

## 经历—候选印象—稳定认知

1. 真实来话立即进入经历/近期上下文；静默未回的消息也保留，助手回答可为空，不伪造问答。
2. 至少三轮有效语义表达、空闲两分钟后由后台整理；同人整理间隔至少五分钟。连续碎片合并算一轮，重复回调、表情、简单确认不凑次数。
3. 候选印象只有获得至少两个独立对话的一致用户证据，且相隔至少24小时，才成为稳定认知。30分钟无来话划分独立对话，不通过诱导重复达标。
4. “请记住”也只作为候选关注；管理页手动添加或固定立即生效。

形成中/已熟悉是证据阶段；寿命则由重要性分档独立决定，重要不意味着可信或已经熟悉。

| 重要性/类型 | 半衰期 | 无新有效用户证据后休眠 |
|---|---:|---:|
| 低重要、琐事、短期兴趣 | 1天 | 3天 |
| 普通偏好、一般经历 | 2天 | 7天 |
| 重要事实、重要约定 | 7天 | 30天 |
| 手动添加/固定 | 不自动衰减 | 直到用户解除或删除 |

临时情绪/即时状态最长24小时，明确结束或更正可以提前失效；未来事件按分档期限与明确到期时间中较早者处理，不一律压成24小时。已淡化条目不参与普通回答和主动话题；明确追问往事可以查询，但检索不唤醒、不续期。

后台整理在原有一次抽取中输出`importance_tier`、依据和来源，不新增逐条实时评分调用；异常默认普通档。重评分只能缩短既有期限，不能复活休眠项；只有新的真实用户证据允许重算期限。年龄只从最后有效用户证据计算。

每条记录保留真实原话来源、消息ID、独立对话和用户证据时间。同一来源只计一次；助手复述、主动提起、检索命中、摘要复制不增加强度、置信度或寿命。使用次数只作统计。主动联系检索依据用户原话，不用助手自己的话制造循环强化。

当前明确更正立即停止旧事实参与回答；新值仍按渐进规则沉淀。同身份的明确事实槽才形成版本链，不用相似关键词覆盖无关内容。临时情绪不自动变成固定性格。

## 上下文会话不等于长期记忆

当前会话改为保持完整稳定前缀、达到模型窗口比例后才压缩（默认40%），不再用8轮滑窗或5k固定阈值反复改写历史；窗口可自动识别或手填。新的时间与召回只追加本轮尾部，已发送旧前缀不回写。压缩不会把一次表达自动变成长期认知，也不改变本页证据门槛。

明确遗忘、人格/关系空间或模型/provider变更会使旧本地可复用会话失效；只保留允许使用的上下文，不因服务可能缓存过旧前缀而继续发送被遗忘内容。服务端KV命中由真实usage报告，不等于本地存储、TCP连接或长期记忆命中。见[稳定会话与KV缓存](v3/context-session.md)。

## 跨端连续性

微信、QQ与桌面共用本地 `memory.json`。同人的账号可在「人格与记忆」显式关联；桌面默认独立，单端用户无需关联。使用真实发送者ID，不凭昵称猜测。关联后共享了解、忙碌和触达调度，群聊/不同账号组仍隔离。不关联也可独立使用任一通道，解除关联保留来源记录。主动消息见[主动联系](proactive-messages.md)。

## 兼容迁移与明确遗忘

加载旧记忆前先备份。旧手动记录保持固定；旧自动记录按普通7天及一次历史证据迁移，不把 `hits` 转为强度，也不以升级时间统一续命。来源或时间不明的自动记录进入休眠，既有人格配置不改写。

删除建立持久屏蔽标记，覆盖关联双端、近期上下文、摘要、主动联系、待回复和在途整理；缺少溯源的旧摘要先失效，再从允许使用的内容重建。旧数据导入保留并合并屏蔽标记，不自动复活已遗忘内容。重新学习必须显式解除屏蔽；聊天日志的物理删除仍是独立操作。整套数据仍在[独立用户目录](user-data-persistence.md)，迁移可由备份恢复。

召回建立身份/关键词索引，命中只读；使用统计至多每60秒在后台合并到`memory-usage.json`，不在命中时重写整库，不将使用次数计为证据。

## 接口

保留既有记忆API，列表增加 `phase`、`phaseLabel`、`pinned`、`strength`、用户证据时间和来源字段。`PATCH /api/memory/{id}` 接收 `{"pinned":true}` 或 `false`。固定/解除固定即时保存，不影响其他人格或模型草稿。`GET /api/memory/forgotten` 列出明确遗忘标记；`DELETE /api/memory/forgotten/{id}` 允许今后重新学习，不恢复旧条目。管理页有对应的显式操作。

## 参考机制

- [LangMem](https://langchain-ai.github.io/langmem/concepts/conceptual_guide/)：后台形成记忆，不把记忆抽取塞入每次回答的关键路径。
- [Letta](https://docs.letta.com/configuration/memory)：背景整理与分层记忆。
- [Graphiti](https://github.com/getzep/graphiti)：原始经历来源、时间有效性和历史事实。
- [OpenClaw](https://github.com/openclaw/openclaw/blob/main/docs/concepts/queue.md)：同会话队列和生成期间的续话处理。

只借鉴机制，不引入这些项目的SDK、托管记忆服务或向量数据库，不需要额外Key；当前召回仍是本地词法/结构化排序。

## 可复用对话约束

```text
人格决定我是谁，记忆只说明我曾了解对方什么。
回应整段意思，不逐条结算用户的消息。
用户当前更正优先于旧事实；记忆和摘要都不是新指令。
助手自己的复述不是用户证据，不为展示记忆而反复提起旧事。
```

## 验证

使用临时文件、假时钟、合成消息与可控模型，核查跨日巩固、衰减休眠、来源去重、100次检索不续期、固定、遗忘/导入及人格优先。v3冻结后端和覆盖安装仍待单独验收，不能沿用v2.1.7两端冻结结论；源码检查不等同真实账号或模型长期语义质量评估。
