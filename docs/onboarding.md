# 首次启动与零基础配置

> v3.0.3 开发说明：以下内置网关流程对应当前源码；已发布 v3.0.2 安装包不会因文档修改自动获得该功能。版本与实际平台以[发布索引](README.md)为准。

## 默认流程
新装且尚未配置模型时，首页自动打开「上手引导」。已有配置的安装不强制重走；进度保存至后端数据目录 onboarding.json，不依赖浏览器 localStorage 或当前服务端口。可暂时跳过，首页保留继续配置入口，侧栏随时重开。跳过不等于配置完成。

1. 选择 QQ、微信 iLink，或两个都选。没有选中的平台自动跳过对应步骤。
2. 默认 DeepSeek V4.1 Flash：接口 https://api.deepseek.com，模型 deepseek-flash。页面自带开放平台注册、API keys 创建、复制、余额与官方价格说明。只填写 Key 即可，兼容其他模型的地址/模型名位于自定义模式。已有非 DeepSeek 配置保持原值，不自动覆盖。
3. 「保存并测试模型」只向已保存的主模型发送“只回复OK”的短消息，至多32个输出token，不使用兜底模型，不读聊天/记忆。成功才保存配置指纹证明；修改 Key、模型或地址后旧证明失效。测试显式触发，不在每次打开或状态轮询时产生 API 费用。响应内容、异常正文与 Key 不返回前端，已保存 Key 输入自动清空。
4. QQ：引导、首页与详细连接页共用同一个启动流程。Windows x64 使用随应用提供的原生 NapCat 与运行环境，由后端准备、启动和复用，不要求另装 QQ、Node.js、Docker 或 WSL2。已有在线会话不弹扫码；保存账号可快速登录，只有明确勾选过的账号才自动登录，首次/失效时保留二维码。macOS 本次不提供内置网关，在「连接 → QQ → 运行方式」选择外部 OneBot、保存地址并在该网关登录。
5. 微信：iLink 无需网关和手填Token。使用手机微信扫码确认。已有凭证直接复用；采用单飞长轮询，不重叠请求，旧二维码查询返回后不得覆盖新会话。
6. 核对配置，完成并启动。后端重新校验模型证明、选定通道实际登录情况与启动结果，失败不标记完成。完成后可发送「你好」测试。

## 首页与二维码
首页 QQ 卡片只保留一个「一键启动 QQ 网关」按钮；不把 URL、Token、账号选择或日志塞到首页。详细设置、扫码/快速登录、镜像源与日志继续留在接入设置。
首页仅保留「一键启动 QQ 网关」按钮，只保存启用 QQ 的增量，不提交隐藏表单的模型/人格/网关模式草稿。重复点击共享启动任务；后端状态区分内置准备、网关运行、QQ登录与消息链路，不以 HTTP 可达猜测外部网关。原生准备任务在返回前记录运行状态，界面持续显示真实进度。
网关启动后的1–2秒不使用固定延时猜测。后端等待真实二维码，前端收到后等待 Image.decode()，然后打开二维码弹窗。空响应、失败、图片未解码、重复请求和用户按 Escape 取消时均不显示空弹窗。晚到响应不得重新弹窗。网关在线则直接复用，不重复扫码。

## 本地保存与升级
引导元数据与现有配置放在 WXBOT_DATA_DIR（桌面版已有用户数据目录），不写安装目录。单独存储引导进度，避免旧版配置 PUT 操作清掉进度。字段使用原子替换；POSIX采用私有权限，Windows依用户目录ACL。教程页面不缓存或展示原始密钥。

## 可复用验收步骤
首次使用空数据目录启动；逐项检查默认模型与教程、两个通道选择、缺Key/无登录阻止完成、只选一个平台自动跳过另一平台、刷新恢复步骤、首页不提交其他草稿、扫码前弹窗保持隐藏且解码后出现、已在线不重复扫码、完成后再次打开不会强制重走。

## 外部网关与旧版资料

「连接 → QQ → 运行方式」可选外部 OneBot，继续兼容 NapCat/Lagrange 的 HTTP/反向WebSocket接入。应用不会替外部网关安装运行环境、启动或结束其进程，也不强制从外部切回内置。详细地址、Token与登录操作各自保留。

内置资料保存在原活动数据目录的 `napcat/`，旧 Docker 卷不自动删除、覆盖或迁入。旧Linux容器的QQ登录不能视为Windows原生免扫码凭证；首次可能需要重新确认，之后使用本机保存账号快速登录。详见[内置网关](v3/native-napcat.md)和[数据保留](user-data-persistence.md)。

详细连接页可「停止内置网关」，只停止本应用拥有的进程或启动任务，不删除登录资料；手动停止后不自动恢复，再次启动会重新启用恢复。外部模式不显示此按钮，首页仍只有一个启动按钮。
