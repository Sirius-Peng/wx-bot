# 微信角色语音 · v3.0.2

更新：2026-10-28，随 v3.0.2 提供；实际平台与本轮验证见[发布记录](../release-v3.0.2.json)。原有数据目录、登录、人格和记忆文件不改变。

## Fish Audio 上手

1. 重启包含此功能的后端，到「设置 → 模型接入 → 微信角色语音」。
2. 默认服务是 Fish Audio，音色 ID 已填入公开的[弗洛洛社区音色](https://fish.audio/zh-CN/m/5b432f747d00419aba7cb12fa50e4af0/)。这是公开音色页面，不代表本项目已完成真实合成、训练或音质认证。
3. 到 [Fish 开发者页面](https://fish.audio/developers/) 获取独立 API Key，填入并点击该卡自己的保存按钮。不是 DeepSeek Key，使用 Fish 自己的额度与计费。
4. 先保存再点「生成试听」。试听只在管理页播放，不向微信联系人发测试消息。默认明确请求 `s2.1-pro`；切换引擎前确认自己的额度。错误模型名称、重定向或接口异常不会自动改用另一付费模型重试。
5. 开启语音。默认普通短回复按稳定抽样选择约25%，同一联系人至少间隔5分钟；最多160字、音频最长60秒、单文件8MiB。比例0时只对明确的“用语音回复”等请求尝试，字数/格式和配置要求仍适用。

语音是正常完整文字回复后的可选附件。文字先到，合成在后台进行；不增加一次LLM判定，不让合成拖慢下一轮文字。代码、链接或长内容不朗读；合成失败只显示管理页诊断，不把Key/配置错误发给微信对方，也不重发已完成的文字。

用户说“不要语音”“文字就好”可停止对该微信联系人的后续自动语音；明确要求“用语音回复”可解除。偏好不写入人格或长期记忆文件。

## 微信发送的形式

当前默认发送可播放的 **WAV音频文件附件**，文件名标注“合成语音”，不是承诺微信原生按住播放的语音条。腾讯当前[媒体路由](https://github.com/Tencent/openclaw-weixin/blob/main/src/messaging/send-media.ts)将音频按文件发送，官方仓库仍有[VOICE接口成功但手机端不显示的反馈](https://github.com/Tencent/openclaw-weixin/issues/215)。本功能不靠未核实的字段组合伪装语音条。

附件经过官方CDN上传所需AES加密。上传和发送保留原音频、密钥、context_token及client_id，接口提交后不重新合成另一份音频；接口接受只表示API确认，不等于已播放或原生气泡渲染确认。新来话、设置/人格变化和明确遗忘会取消尚未提交的旧附件。

## 本地 GPT-SoVITS（可选）

用户当前选择的是 Fish，无需部署训练环境。若以后切换本地，可启动上游 `api_v2.py`，填写服务地址、服务端参考WAV路径及对应文本。客户端向 `/tts` 请求完整PCM WAV，不把Fish Key发送给本地服务；训练框架与大权重不进入机器人安装包。

已核实的中文弗洛洛训练库、GPT-SoVITS角色权重及来源条件见[语音资源说明](voice-sources.md)。原始语料与可直接推理的角色模型不是同一种文件，不把英语RVC变声模型当成中文TTS。

## 本地状态与验证

- 配置使用现有 `config.json` 内独立 `voice` 段，Key返回管理页时脱敏；旧全量配置客户端不会清空新语音配置。显式清除Fish Key会同时关闭自动语音。
- 可选附件状态在 `voice-replies.json`；传输队列为原iLink目录的 `audio-outbox.json` 与 `voice-outbox/`。提交前取消和确认后可清音频缓存；未确认的提交保留原凭据，不在重启后自动重新合成。
- 普通合成开始前预留冷却，失败后短时退避，最多2路合成/4个待处理联系人；付费HTTP合成不自动重试、不跟随307/308二次POST。
- 管理接口：`GET /api/voice/status`，`POST /api/voice/preview`（仅 `text`），`PATCH /api/config/section/voice`。沿用管理鉴权与同源校验，预览响应不缓存。

回归使用临时配置、模拟Fish/模型/微信API与合成PCM测试夹具，没有调用真实付费Key或向真实联系人发消息；客户端实际试听与投递需要配置自己的Key并核对手机端。
