### 质量评估与隔离诊断状态

编排进入 `08-evaluate` 后主动停止，用于隔离CPU性能诊断。该次停止捕获到NativeExit=-1、SSH退出255；它们不是前面训练、导出或100次CPU测量失败的结果，不作为模型质量结论。**该原编排保留失败状态；后续独立候选已完成开发质量回归，不能把原编排状态改成成功。**

隔离新进程诊断已进行线程、FTZ和P核对照。其中一次**30次**P核子进程对照得到p50 **212.57ms**、p95 **216.55ms**、最大 **217.43ms**。这是小样本诊断，不是100次正式复测，也没有完成新策略的1998条重校准和质量评估；当时不据此宣称候选达标；后续100次结果见下文。

FTZ在当前有效诊断中基本没有帮助，关闭spinning反而更慢，二者均不启用为默认优化。FTZ的主线程设置受首个session初始化影响，先前在同一进程内切换的probe已保留，但不作为FTZ效果证据。

P核对照的动态mask只作用于测试Python自身进程，没有修改系统、父进程或其他进程的亲和性、优先级和电源配置，也不把该机器的mask或核号写成通用固定值。真实worker已实现可选 `prefer_performance_cores` 策略：仅当前工作进程、动态识别最高EfficiencyClass且原mask允许的全部核心（含parked），至少4个物理核、单processor group；非混合架构或API失败保留原mask并记录原因。默认不强制启用，候选policy显式开启。4线程加此策略的1998条重校准、100次CPU复测及开发质量回归已经完成。原CPU基线和所有失败/无效probe保留，新策略使用独立候选目录，不覆盖基线。

选定选项后，必须让实际发行worker部署相同配置，再重新完成量化后校准、质量评估和100次CPU复测，不能只修改benchmark获得更漂亮的数字。诊断结果改变推理数值或图结构时，旧校准与质量报告不自动继承。

### 真实worker：100次复测及质量结论

`run-v4-pcores` 保持模型和tokenizer字节不变，仅将认证policy设为4线程、`prefer_performance_cores=true`；FTZ关闭、spinning不覆盖ORT构建默认。校准实际使用同一worker，1998条重校准约87.29秒，保存所选拓扑、原mask/实际mask、provider、策略及哈希。性能核全部由本机拓扑推导，不将诊断中的mask写成硬编码。

不含Torch的RuntimePython、ORT1.23.2、CPUExecutionProvider，每长度100次：

| 实际输入 | p50 | p95 |
|---|---:|---:|
| 32 token | 39.9496ms | 41.5423ms |
| 128 token | 114.7110ms | 119.0680ms |
| 256 token | 217.8681ms | 225.7005ms |

含哈希冷加载2763.66ms，进程峰值RSS1,831,415,808字节。相比原2线程全核基线，**4线程与性能核组合**将256-token p95从1397.94ms降至225.70ms，本机速度目标通过；这不是所有Windows设备或整段LLM聊天的性能承诺。评测器另外独立重复同长度测速，p95为224.63ms。

### 独立运行策略候选的复测流程

1. 用 [tune_runtime.py](../../tools/decision_model/tune_runtime.py) 从已校验的基准包创建新候选，仅调整明确支持的policy字段；模型和tokenizer字节不变，原pass/evaluation不继承。候选创建使用开发校准环境，需要scipy等研发依赖；不因此把这些依赖塞入发行环境。P核policy与候选工具的对应选项以实际实现及 `--help` 为准，不用外部诊断脚本的参数冒充产品接口。
2. 在隔离新进程、实际worker选项下，对原1998条calibration重新推理并拟合，保存policy/模型/校准哈希和运行信息；不读test/stress调阈值。
3. 用不含Torch的RuntimePython启动新进程，实际部署相同线程/P核策略，每输入长度100次测量CPU；保存有效的mask选择或弃权原因，不用另加一套benchmark专属绑核实现。
4. 另起新进程运行开发集质量回归，保留静默精确率、应答召回、保护切片、覆盖和数据资格原因。当前数据仍是开发回归，不会因速度改善或换策略清除独立性门；Gather UINT8候选也要单独重复校准、质量和CPU流程。

源码绑定也已收紧：export从实际 `training.json` 记录训练split、checkpoint及训练元数据哈希；评测验证模型的校准SHA等于当前calibration，并绑定实际训练split，而不是只相信后来提供的 `dataset.json`。旧包缺证据、weights-only续训历史未验证或split错绑时，评测仍保留开发诊断，但独立性门不放行；不从新目录或说明文字补造历史。
