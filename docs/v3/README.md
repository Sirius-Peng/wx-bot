# v3.0.2：轻量陪伴内核

更新：2026-10-28。v3.0.2 正在构建与验收，平台、摘要与本轮结果见[新版发布记录](../release-v3.0.2.json)。当前公开发布仍为[v3.0.0](https://github.com/Sirius-Peng/wx-bot/releases/tag/v3.0.0)，其[历史发布清单](../release-v3.0.0.json)及v2.1.7附件保持不变，不将旧验收记为新版结果。

## v3.0.2 更新

- 微信角色语音：独立 Fish Audio Key、引擎选择与试听；文字先行，部分短回复后台合成为 WAV 文件附件。具备冷却、退订、抢占取消和原凭据续投，不是微信原生语音条；真实付费合成与手机端播放未验收。见[语音设置](wechat-voice.md)与[资源来源](voice-sources.md)。
- 历史日期：区分用户发送、首次接收和助手投递时间；历史相对日期参照原发言时点，无依据的日期保持未知，不以升级时间给旧事续日期。见[历史时间说明](history-time.md)。
- 首页重新排布运行状态与连接/陪伴卡片；设置分组、卡片独立保存、切页草稿保留和未保存提示。伙伴按钮/快捷键/托盘仅关闭伙伴，后台继续，不因加载就绪重开已关闭窗口。

## 保留的轻量内核功能

### 四个主页面

| 页面 | 用途 |
|---|---|
| 首页 | 运行状态、QQ 一键启动、桌面伙伴开关/导入/打开，以及消息记录和首启引导入口 |
| 接入设置 | 微信 iLink、QQ NapCat、登录/快速登录、回调连接与日志 |
| 人格与记忆 | 完整人格独立保存，对用户的了解、来源、固定/遗忘、可选身份关联，简要词频/话题气泡 |
| 设置 | 主/备用/判定/视觉模型、fast/deep、搜索与时间、回复、主动联系、记忆、备份/导入和桌面设置 |

完整拓扑界面不再作为 v3 功能。旧拓扑和统计 hash 引导到记忆页；原本地资料不因此删除。消息记录和上手引导保留，但不占用侧栏入口。

### 一个内核，三个通道

微信、QQ、桌面会话复用收集、决策、上下文、记忆、生成和投递编排。协议适配器保留各自的接纳和可靠投递方式；QQ群聊仍只在被 @ 时回应。

桌面伙伴默认是独立 `desktop:local` 账号，不自动推断其对应的微信/QQ身份。单端用户无需做身份关联；需要共享的用户可以显式关联。桌面流式事件带轮次及序号，增量只作草稿，完成后才保存最终内容；重连按持久完成事件恢复，不重新生成。

桌面形象默认是静态标记，可导入本地 Live2D 目录。导入保留模型自身相对路径，通过模型清单核对资源；多清单目录需要选择。形象资源留在原活动数据目录的 `companion/models/`。桌面伙伴仅文字，没有桌面语音输入、语音合成或默认下载角色模型；可选微信语音附件是独立功能。托盘提供伙伴恢复入口；鼠标穿透后可以从托盘恢复。

### 人格优先，记忆更轻

2026-10-20 新增：[人格预设 × 关系模式独立记忆空间](persona-spaces.md)。切换使用另一套事实、上下文与学习队列；各组合保存自己的 `persona.json`，旧根文件不移动；身份关联、联系时间与明确遗忘仍共享。

人格身份、口吻、价值观及关系边界始终由人格配置决定。记忆只作为参考资料，重要性与可信度独立：被判断重要不会增加证据次数，更不会把一次陈述直接变成稳定事实。

| 类型 | 半衰期 | 最后有效用户证据之后休眠 |
|---|---:|---:|
| 低重要、琐事、短期兴趣 | 1天 | 3天 |
| 普通偏好、一般经历 | 2天 | 7天 |
| 重要事实、重要约定 | 7天 | 30天 |
| 手动添加/固定 | 不自动衰减 | 直到用户解除或删除 |

临时情绪、即时状态最多24小时；未来约定按分档期限与明确失效时间中较早者处理，不一律压成24小时。休眠不物理删除，但普通对话和主动话题不使用。检索、助手复述、摘要复制和模型重评分不续命；重评分只允许缩短既有期限，只有新的真实用户证据才能重新计算期限。

后台整理仍要求至少三轮有效语义表达、空闲两分钟、同人整理间隔五分钟；稳定认知仍要求两次独立对话的一致用户证据，且相隔至少24小时。“请记住”也不绕过沉淀门槛。日常只召回0—1条相关记忆；明确追问事实或往事时才允许最多三条、400字。

### 等得更短，不在每句后抢答

- 完整表达默认2秒；碎片、未完句及附件说明4秒；按最近20个有效发送间隔调整，最高6秒。
- “说完了”约0.3秒接答；“等我说完”保持等待，120秒后只重新判断。10秒不是发送期限，50条不是表达结束。
- 生成、识图、搜索或限流等待中的新输入使未提交草稿失效；提交开始后沿用原正文和凭据。
- 图片到达即可预取，下载并行3、解码并行2，缓存180秒/64MiB；不因提速丢掉正常图片或将视频当图片。单轮图片数量等原约束仍保留。
- 真正决定回应后才显示正在输入；等待、静默不发占位气泡。

等待窗口内约0.8秒防抖后，可取消的云判定与图片预取/本地检索并行。同一连续输入批次只开放一次云判定额度，防抖取消不扣；同一有效预判仅交接一次。新片段取消旧版本但不重开额度，最新全文仍走保护/确认/未完句规则，模糊时保守回应而非套用旧静默结论。实际收益仍需端到端测量，不用历史ONNX或单次API推理数字代替用户从发送到收到回复的时延。

### 稳定会话前缀与按窗口压缩

顺序为：`完整稳定人格 → 已发送完整会话前缀 → 新轮资料/时间/媒体状态 → 当前完整来话`。

- 不再按8轮滑动历史或5,000 token固定压缩；默认达到模型窗口40%才整理旧历史，窗口自动识别或手填、压缩比例可配置。
- 官方DeepSeek `deepseek-flash` / `deepseek-v4-pro` 当前窗口为1M；未知模型自动用32K保守值，实际供应商不同可手动调整。主模型与Key保持可配置，不为缓存强换模型。
- 已发送的前缀保持原字节及顺序，新的时间/检索等只追加本轮尾部。压缩、明确遗忘、人格或供应商/模型变更使旧本地会话失效，不跨用户复用。
- 服务端缓存尽力而为；HTTP连接复用不是KV命中，只有usage返回真实hit/miss才记为缓存统计，缺失显示未知。详见[稳定会话与KV缓存](context-session.md)。
- 动态资料共用800估算token，搜索证据整轮额外最多2000；包装文字也计入。
- 人格、当前来话、媒体和输出预留独立考虑，不静默截断当前表达。
- 记忆召回使用身份/关键词索引，只读命中；统计在后台至多每60秒合并一次，不在每次命中时重写整库。
- 日常默认 `fast`，深度模式 `deep` 可独立切换。只对已确认支持的接口传入相应参数，保留已有模型及 Key。
- 2026-10-25默认接入[官方直接Search / Fetch](search-1017.md)，正文/摘要依据后一次整合，Fetch仅按需，整轮工具合计最多两次并按次额外计费；原native辅助模型保留手动兼容、按需复核，不隐式双后端重试。
- 成功公开搜索query可短缓存60秒并合并相同在途请求，复用连接且按Key/模型隔离；这不是供应商KV命中。设置手动诊断显示当前运行近期最多500条用量事件，按真实输入token加权；缺失未知、覆盖不全不报总体命中率，思考不重复加到输出。v2.1.7旧版实证及费用边界见[调用与费用核查](cache-cost.md)，不从17M/30元推断命中或省费比例。

## 兼容性约束

| 平台 | 活动数据目录（保持原值） |
|---|---|
| Windows | `%LOCALAPPDATA%\WxBot\user-data` |
| macOS | `~/Library/Application Support/WxBot/user-data` |
| Linux | `$XDG_DATA_HOME/wxbot/user-data`，缺省为 `~/.local/share/wxbot/user-data` |

应用 ID 继续为 `com.siriuspeng.wxbot`；`WXBOT_DATA_DIR`、`WXBOT_USER_DATA_DIR` 和既有自定义目录语义不变。原配置、人格、微信凭证、记忆和投递文件不重命名；新功能增加独立文件，不迁走原资料。

旧自动记忆缺少重要性字段时按普通档及原证据时间处理，不在升级时统一续命；没有可信依据或时间的进入休眠。旧人工记忆保持固定，不启动时全库调用模型重评。备份/导入仍合并遗忘屏蔽标记，不能以旧资料恢复被明确遗忘的信息。

v1.3.6/v2.1.4/v2.1.7覆盖升级合成夹具与原生安装生命周期分开记录；具体通过/未执行范围见[新版发布记录](../release-v3.0.2.json)及[验收记录](validation.md)，不以夹具替代实际安装。

## 轻量云判定，本地模型已退役

明确问题、请求、更正与情绪诉求由保护规则保障回应；只有模糊私聊需要模型判断。默认使用 `deepseek-flash` 非思考模式，短 `R/D/C` 协议，只发一次请求，判定总期限3秒；失败、超时或解析异常保守回应，控制字段不进入正文。独立判定配置和现有主模型/Key复用规则保持，不覆盖用户设置；主回复仍保留fast/deep。

应用不再导入、加载、预热或下载本地判定模型，安装包不包含ONNX/tokenizers/判定模型资源，也不等待本地训练达标才构建。原Chinese-Jev/Laya工具、固定版本、历史权重及失败评测保持研究用途，不自动删除，也不作为当前发行前置条件。历史Windows两轮CUDA及量化结果见[研究归档](windows-training.md)，当前策略见[接话判定](local-decision.md)。
