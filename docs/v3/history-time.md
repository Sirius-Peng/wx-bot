# 历史消息的日期与时间

更新：2026-10-28，随 v3.0.2 提供；安装包平台与本轮验收见[发布记录](../release-v3.0.3.json)。已有旧版安装包不会因仓库修改自动更新。

## 不再把旧话当成刚才

历史消息传给模型时附加独立的绝对日期、时间及时区说明，不改用户原话，也不把这些说明发给聊天对方。默认使用已有的 `context_timezone`（Asia/Shanghai），可沿用设置中的其他时区。

例如，用户在 **2026-10-23** 说“昨天完成了任务”，到 **2026-10-27** 再接着聊时，没有另设时间参照的历史直述“昨天”锚定 **2026-10-22**，而不是10月26日。引述、转述或文中明确指定的其他日期优先，不按关键词硬改原话。“刚才”也只相对于那条原话的时点，不代表这轮刚发生。

- `user_at`：平台提供的发送时间；平台缺失时保留首次本机接收记录时间，并明确标记来源。
- `user_end_at`、`source_times`：连续输入的范围与每条原始消息时间。跨午夜批次保留原消息序号与日期边界。
- `received_at`：首次接收记录时间，不由重复回调或回复完成时间刷新。
- `assistant_at`：助手完成投递的时间，单独记录；主动联系和稍后回复同样保留，不伪造新用户发言。
- `user_time_source`：区分平台发送时间、接收记录时间和部分消息时间缺失。

这些都是现有 JSON 的兼容增补字段；活动目录、文件名、身份关联、人格和登录凭证不改变。

## 旧记录与摘要

有旧 `ts` 时标为旧版记录时间，不假设它一定等于事件发生日；确实无依据的日期标为未知。升级、导入、文件修改时间、检索命中与后台整理时间都不用于给旧事补一个“今天”。

摘要整理会收到逐条日期，要求保留事件与来源日期的对应，并把可确定的相对日期转为绝对日期；缺少依据或有歧义则保留未知。摘要还附带可核实原始记录的时间范围，范围不等于每个事件都发生在同一天。长期记忆的“获知/证据记录日”与事件发生日分开标注。

## 缓存与后台记忆

时间协议或配置时区变化会令旧的无日期会话前缀重建一次。之后仍复用已持久化的完整前缀；绝对时间标记不随日期变化重写，不增加日期判定的模型调用。用户、助手原文、多模态输入及工具调用协议保持原样。

本次不改变记忆形成门槛、证据计数、重要性、遗忘期限或检索续命规则。后台整理仅额外使用已有来源时间，不能因为整理得更晚就把一条旧证据变成新证据。
