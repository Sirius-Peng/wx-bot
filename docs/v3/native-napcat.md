# 内置 NapCat 与外部 OneBot

v3.0.3 开发说明，2026-10-28。以下对应当前源码，不代表已发布v3.0.2附件已经包含内置网关；正式平台、固定上游与验收以最终发布清单为准。

## Windows x64：一个按钮

首页保留「一键启动 QQ 网关」。Windows x64 使用随应用提供的原生 NapCat 与运行环境，不要求另装 QQ、Node.js、Docker、WSL2或系统服务。后台负责准备、配置和启动自有进程，界面按真实任务显示进度；不是固定等待两秒便宣称就绪。

已有在线会话直接复用。保存账号可选择快速登录，勾选后才设置下次自动登录；首次、验证或会话失效时仍可扫码。只有后端返回实际二维码且浏览器完成图片解码，才打开弹窗；取消后晚到结果不重新弹出。QQ在线、消息接口可达、推送链路与机器人启动是不同状态。

## 运行方式与外部网关

在「连接 → QQ → 运行方式」选择：

- **应用内置（Windows x64）**：只管理本应用自己的网关进程；配置与账号在原活动数据目录的 `napcat/`。应用不接管或结束用户另行运行的QQ。
- **外部 OneBot 网关**：手动填写已有NapCat/Lagrange等网关HTTP地址与Token，在该网关完成登录；继续支持反向WebSocket或HTTP上报。本应用不下载、启动或停止外部进程。

本次macOS不提供内置网关，应连接已部署的外部OneBot，不以Docker作为隐式后备安装。页面按照后端明确的 `manager.mode` 显示，不通过HTTP是否响应猜测网关归属。修改模式要用通道卡自己的保存按钮；首页启动不提交隐藏表单的模式、人格或模型草稿。

## 数据与升级

应用ID、活动数据根、现有人格/记忆/微信凭据与文件名不变。新安装默认 `napcat_mode=native`；旧文件缺少mode但已启用QQ、持有WebUI/OneBot Token、QQ号或非默认HTTP地址时保留external，不自动改写或接管已有网关。用户明确切到native才部署本机网关。

新增 `napcat/` 跟随现有本地资料保存，原Docker卷保持原样，不自动删除、覆盖或迁入。旧容器的Linux QQ登录不等同于Windows原生登录凭据，首次可能需重新扫码；之后可复用本机保存账号。外部网关资料继续按其自己的路径备份。

实际子目录为 `napcat/runtime/v4.18.41/`（固定版本缓存）、`work/config/`、`work/logs/`、`profile/`（完整QQ账号）、`logs/process.log` 和 `manager.json`（端口与恢复状态）。成功就绪后启用下次后端启动恢复；连接页「停止内置网关」只对本应用拥有的运行进程或启动中任务开放，手动停止关闭自动恢复，重新启动网关后重新启用恢复。外部模式不显示此控制。停止会关闭登录弹窗并使在途二维码/登录确认失效，不在停止后重新弹出。退出后端只结束自有进程树，不清除账号、配置或恢复标记。

旧 `napcat_image_mirror` 仅为旧配置兼容，不在界面中作为原生下载源，也不改用户的全局下载配置。更多见[数据持久化](../user-data-persistence.md)、[旧目录导入](../data-import.md)与[首次配置](../onboarding.md)。

## 当前验证边界

前端VM行为回归覆盖无Docker准备、显式内外部模式、仅增量保存、首页单按钮、跨平台提示和原二维码/快速登录流程。实际Windows原生启动、QQ真实登录、安装包内资源与生命周期由本轮原生验证独立记录，不使用前端桩冒充已登录真实账号。

运行前在后台核验705份固定发行文件及其完整索引摘要，拒绝任意额外脚本、DLL和符号链接。QQ原生库会在运行目录生成唯一的非执行诊断 `beacon_report.log`；本应用仅允许这一个已核实的运行日志，进程结束后将其受限尾部保存在 `work/native-beacon-report.log`，不把它当成发行文件或放宽其他文件校验。托管标准输出在写入日志前隐藏Token与链接；私有上游工作目录不随安装包发布。
