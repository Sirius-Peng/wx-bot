# 人格预设 × 关系模式：独立记忆空间

更新：2026-10-28；功能初次记录：2026-10-20。本文说明v3.0.2保留的人格预设与关系模式独立空间，原始设计及源码测试范围保留；当前发布平台、原生资源与未执行项目见[本次发布清单](../release-v3.0.2.json)，[v3.0.0清单](../release-v3.0.0.json)仅记录原发布，不将源码夹具当作完整安装验收。

## 使用时会发生什么

在“人格与记忆”中切换**人格预设**或**关系模式**，就会选择另一套记忆空间。两项共同决定归属，例如：

- `phrolova--neutral`：弗洛洛／普通聊天。
- `phrolova--trusted`：弗洛洛／信任日常。
- `phrolova--rover`：弗洛洛／漂泊者剧情扮演。
- `custom--neutral`：自定义人格／普通聊天。

当前预设为 `phrolova`、`custom`，关系模式为 `neutral`、`trusted`、`rover`。修改名字或人格文字本身不创建新空间；同一个 `custom` 预设与同一种关系仍使用同一空间，不会依据文字内容偷偷拆库。

**首次进入新组合时，不复制旧组合的用户事实、对话或摘要。** 切回原组合会继续使用它原来的文件，不把两套经历混在一起。单端用户照常使用，不需要先关联微信和 QQ。

### 每个组合也记住自己的名字与人格文字

每套空间有独立的 `persona.json`，保存名字、人格补充文字、预设与关系模式；这些设置不是长期记忆，不会写成 `memory.json` 的用户事实。

- **只切换预设／关系**，且没有同时改动名字或人格文字：恢复目标组合已经保存的人格快照，并同步 `config.json` 兼容字段。
- **切换时同时改了名字／人格文字**：使用这次明确保存的新文字，不用旧快照把编辑覆盖掉。
- **目标组合还没有快照**：按此次保存的人格字段建立初始快照，用户记忆仍为空。
- 如果配置已经保存、程序却在运行时切换完成前退出，重启会结合索引、上一活动快照和保存字段恢复目标设置；明确编辑的文字继续保留。

例如，A 组合叫“甲”、B 组合叫“乙”，仅切回 A 后会恢复“甲”，而不是把“乙”写进 A 的人格文件。

## 哪些隔离，哪些共享

| 数据 | 行为 |
|---|---|
| 用户事实、候选印象、长期认知、固定记忆 | 每个组合独立；不复制、不混库 |
| 真实上下文、跨端可用历史、摘要及来源 | 按空间选择；其他空间的对话不进入当前回复上下文 |
| 自动记忆整理队列、证据、使用统计 | 每个组合独立；旧任务不向新空间写入事实 |
| 名字、人格文字、关系设置快照 | 每个组合独立 `persona.json` |
| 微信／QQ／桌面账号关联 | 全局身份元数据；关联不等于跨人格共享事实 |
| 联系时间、免打扰与同人触达约束 | 全局共享；切换不能重置冷却、制造重复主动联系 |
| 明确遗忘屏蔽 | 全局共享，覆盖关联渠道与所有人格空间 |
| 登录凭据、平台收件／投递账本 | 保持原路径与可靠投递规则，不随人格搬迁 |

关联微信与 QQ 后，它们在**同一个人格空间内**可以使用同一人的记忆；关联不会把另一个人格空间的事实拷贝过来。未关联账号仍独立工作，不自动猜测身份。

### 明确遗忘不是“换个人格就忘掉删除操作”

管理页明确遗忘会保留全局屏蔽标记，同步清理各空间中的相关可用事实、上下文与摘要，并阻止旧整理任务或旧数据导入让内容复活。

之后解除屏蔽只是允许未来重新学习，**不会恢复其他空间已经被清理的事实**。聊天日志和备份的物理删除仍是独立操作；历史日志不因此变成可召回的长期记忆。

## 切换发生在对话中间时

- 来话带有接纳时的人格空间标记；旧版本无标记记录只归升级时绑定的旧空间。
- 旧空间尚未提交的来话只留在原空间，不改用新角色重新回答；旧补回计划会取消，不把旧话题跨人格追发。
- 已经开始平台提交的回复继续沿用**原正文、原投递凭据**，不重新生成一份新人格答案。
- 新来话进入当前选择的空间。桌面界面切换会清理旧草稿，并按当前空间恢复事件，避免旧气泡冒充新角色的经历。

因此，切换不等于撤回已经交给平台的消息，也不会自动切换渠道发送旧回答。

## 文件布局与覆盖升级

应用 ID、既有数据根、自定义目录和登录路径不改变。首次升级会在原数据目录的 `.backups/` 中保存升级前快照，并创建 `persona-state.json`。索引记录：

- `legacy_space`：升级时当前配置对应的组合。
- `active_space`：当前组合。

**旧文件不迁走、不改名。** `legacy_space` 继续直接使用原数据根；其余组合使用枚举键生成的子目录，没有任意路径映射。例如，升级前使用弗洛洛／信任日常：

```text
原用户数据目录/
├── config.json                       # 当前配置的兼容镜像
├── persona-state.json                # legacy / active 组合
├── persona.json                      # 旧组合的人格快照
├── memory.json                       # 旧组合，原路径不变
├── context-ilink.json                 # 旧组合上下文
├── memory-learning.json               # 旧组合整理队列（存在时）
├── memory-usage.json                  # 旧组合使用统计（存在时）
├── identity-links.json                # 全局身份关联
├── memory-forgotten.json              # 全局明确遗忘屏蔽
├── conversation-state.json            # 原投递／补回控制路径
├── proactive.json                    # 共享联系时间与带空间标记的历史
├── ilink/                            # 微信凭据原路径
└── persona-spaces/
    ├── phrolova--neutral/
    │   ├── persona.json
    │   ├── memory.json
    │   ├── context-ilink.json
    │   ├── memory-learning.json
    │   └── memory-usage.json
    └── custom--trusted/
        ├── persona.json
        └── memory.json
```

QQ、桌面上下文按需使用同目录的 `context-onebot.json`、`context-desktop.json`。尚无记忆／对话的空间不要求预先生成所有文件。

旧组合不一定是 `phrolova--neutral`，以升级时实际配置和索引为准。不要仅凭文件夹名字手工搬动根 `memory.json`，也不要删除索引后让程序猜测哪套资料属于谁。

## 备份、旧目录导入与恢复

完整备份包含索引、各空间文件和全局控制。导入保留来源整套空间的归属，不把现有目标事实混入来源人格；当前与来源的遗忘屏蔽会保守合并，所有空间摘要和上下文同步过滤。

从没有空间索引的旧版目录导入时，首次绑定依据**导入配置**，不是导入前本机正在选择的人格。存在 `persona-spaces/` 却缺少索引的目录会在导入前报错，应该恢复完整备份，而不是猜测归属。无效组合键、错位人格快照或损坏的嵌套状态也在清空当前数据前拦下。发布导入失败时恢复导入前的整套空间与凭据，原来源目录保持不变。

`persona.json` 已有未知用户内容或索引损坏时会保留原文件，不用默认设置覆盖。备份与导入教程另见[用户数据](../user-data-persistence.md)和[旧目录导入](../data-import.md)。

## 回归入口

仓库根目录运行：

```sh
.venv/bin/python -m unittest \
  tests.test_persona_spaces_runtime_v3 \
  tests.test_persona_spaces_integration \
  tests.test_persona_space_coordination_v3 -q
```

运行时测试包含人格／关系两种切换、独立快照恢复、显式编辑、保存后未应用的重启窗口、事实不复制、共享身份、全局遗忘与解除、原路径及损坏文件保留。协调测试区分旧未提交输入与已经提交的投递，不能用这些源码回归代替 Windows/macOS 原生安装验收。
