# 稳定会话前缀、上下文压缩与KV缓存

更新：2026-10-25。本文说明v3.0.0稳定会话与按窗口压缩策略；首次设计记录为2026-10-23。本次发布平台、原生包与实际验收见[本次发布清单](../release-v3.0.0.json)。机制回归不代表真实API缓存率、账单省费或全部覆盖升级生命周期均已实测。

## 为什么不再每轮滑动历史

每次只取最近8轮，或一到5,000 token就把历史改写成摘要，会不断改变后续请求的共同前缀。当前策略默认保留**完整稳定人格和已发送的会话前缀**，仅在末尾追加新一轮内容；在达到模型上下文窗口的指定比例后，再压缩旧历史，而不是每轮重排和重建此前的消息。

这一策略用于提高前缀可复用性，不表示在客户端保存或直接操作模型的KV张量。聊天仍按模型服务的API提交消息；服务端是否落盘、保留及命中由供应商决定。

## 窗口与压缩配置

「设置」中的上下文选项与主模型一起配置，保留已有模型、Key及fast/deep选择：

| 设置 | 默认策略 |
|---|---|
| 上下文窗口 | 自动识别；也可手填供应商支持的token上限 |
| 官方DeepSeek `deepseek-flash` / `deepseek-v4-pro` | 自动使用当前公开的1M窗口 |
| 其他未知模型或兼容接口 | 自动使用32K保守值；不是宣称该模型实际只支持32K |
| 压缩触发比例 | 默认窗口的40%，可调整 |

官方窗口信息于2026-10-23核对，模型与供应商升级时应重新确认。[DeepSeek模型说明](https://api-docs.deepseek.com/zh-cn/quick_start/pricing/)

窗口自动值不是固定更换用户的模型，也不将第三方同名兼容模型无条件认作官方服务。供应商实际容量不同，应手填真实窗口。默认40%是压缩触发比例，不是只发送40%的当前来话；估算需要计算人格、历史、本轮输入、媒体及输出预留，异常超大单轮不以静默截断来冒充完整理解。

## 保持什么不变

1. 完整人格作为稳定开头；已发送的会话消息保持原字节、顺序及角色，不在每次构建时替换措辞或重选旧例子。
2. 新的时间、检索/记忆参考、媒体状态放在**新轮次尾部**，不回头修改旧轮的时间或资料。旧时间只代表当时那轮，不作“现在”。
3. 新一轮的完整用户输入追加在当轮资料之后；生成成功的助手正文按实际完成内容追加。未提交草稿不冒充已经发生的对话。
4. 达到压缩阈值时，保留必要近期原话并整理旧历史；这是显式的本地会话更新边界，会改变可复用前缀，不承诺压缩前后的缓存连续命中。长期记忆与人格文件不是会话压缩的替代品，也不因此自动改写。

## 会话隔离与失效

- 每个用户、渠道会话及人格空间保持明确归属，不跨用户复用完整会话。身份关联仍需用户明确设置，不靠昵称猜测。
- 人格、关系空间、模型或供应商发生变化时，旧本地可复用会话失效；不会把另一人格或另一供应商的旧消息直接接进当前前缀。
- 明确遗忘会撤销含相关资料的本地旧会话，清理可用上下文/摘要并遵守持久屏蔽。之后不再发送已遗忘内容；这不等于替用户删除供应商已经保存的历史请求或硬盘缓存。
- 压缩和恢复仍保留数据路径兼容，不删除用户文件或登录凭据。原始日志的物理删除是独立操作，不能因日志尚在就重新注入已遗忘资料。

## 媒体会话与请求体预算

稳定前缀包含真实图片时，仍按实际识图模型而非仅按文本主模型计算窗口和输出预留；未知视觉接口沿用保守估算。媒体像素在原活动数据目录内的**本地私有sidecar**中保存，主上下文JSON仅保留引用，加载时还原相同请求；不会为了缓存命中降低图片质量。sidecar不是上传到云端的Files API，也不是共享所有用户的图片池；模型调用仍需向配置的供应商发送被使用的图片。

备份或迁移视觉会话应保留主JSON及配套媒体资料，不能只拷贝一个上下文JSON就声称图片会话完整。明确遗忘会撤销可用会话引用，旧媒体不会据此重新进入请求；原始文件与备份的物理删除仍是独立操作。路径/权限和恢复边界见[本地数据](../user-data-persistence.md)。

截至2026-10-23，官方Flash文档给出单图最多1024视觉token、48MiB请求体和单请求600张上限。本项目对官方接口使用**46MiB内部安全预算**为请求包装留余量，并检查整轮图片数量；不把该限制套给未知兼容接口。[官方图像说明](https://api-docs.deepseek.com/zh-cn/guides/vision/)

字节数、图片数与token窗口是不同约束：即使尚未达到窗口40%，历史媒体逼近协议预算时也应先压缩旧历史；这不会丢弃当前输入中的正常图片。当前完整输入本身仍超限时，只给出一次自然分段提示，原文留在本地并标记尚未完整读取，不在下一轮自动重复注入超大原文、不无限重试，也不声称已经分析完。

私有sidecar、原生Windows磁盘读写、备份与导入，以及真实视觉API效果须单独验收；不预填I/O提速或供应商缓存命中数字。

## 只报告真实缓存用量

DeepSeek的服务端硬盘缓存对重复前缀尽力复用；缓存构建、匹配与清理并非由本地连接句柄控制。复用HTTP/TCP连接可以减少网络握手，但**不等于KV命中**；客户端会话ID、相同模型或相同system文字也不是100%命中的证明。[DeepSeek缓存说明](https://api-docs.deepseek.com/zh-cn/guides/kv_cache/)

诊断仅按API真实返回的`usage`记录：

- `prompt_cache_hit_tokens`：服务报告的缓存命中输入token。
- `prompt_cache_miss_tokens`：服务报告的缓存未命中输入token。
- 其他兼容接口如返回明确的cached-token字段，只标注对应服务实际提供的值。
- 没有返回的字段记为**未知**，不把缺失补成0，不用请求次数或相同前缀长度推算“实际命中”。

缓存比例按已知输入token加权，不取各请求百分比的算术平均；覆盖不完整时只展示已知样本比例，总体仍为未知。思考是输出子集，不重复相加。v3「设置 → 主模型 → 用量与缓存诊断」手动读取当前运行近期最多500条事件，不自动轮询模型，不是账户账单。任务拆分、未知覆盖和旧版实证见[调用与费用核查](cache-cost.md)。

速度与费用对比应同时记录输入、输出、真实hit/miss、首token/完整响应耗时及请求数量，并区分冷/热条件。稳定前缀、短判定请求与连接复用是优化手段，不靠填充无意义内容凑缓存，也不为缓存提前反复改写历史，不在实测之前承诺缓存率、固定延迟或具体节省金额。

## 与轻量接话的关系

接话判定与主回复是不同请求。模糊私聊的判定只需本轮及少量状态，默认deepseek-flash非思考、短`R/D/C`协议、总期限3秒；明确诉求由规则保护。等待期间约0.8秒防抖后可提前判断，同一连续输入批次只开放一次云判定额度，有效结果仅交接一次；新来话取消旧版本但不逐碎片重付，最新全文仍执行规则，模糊时保守回应。判定不携带完整人格、知识库或主回复整段会话来凑缓存；主回复仍使用完整人格和上述稳定会话。

## 验收要点

- 自动官方窗口、未知32K、手填与比例保存，默认40%前不因8轮/5k旧阈值压缩。
- 逐轮请求比较：旧前缀完整不变；新时间/检索只影响新尾部；跨用户、人格/provider变更与明确遗忘不复用旧会话。
- 触发压缩及重启恢复后，当前来话完整、来源/遗忘约束仍有效，不出现重复助手稿。
- 以真实usage区分hit/miss/未知，连接复用不伪造命中；Windows主验证机与实际模型分别记录端到端时间和用量。
